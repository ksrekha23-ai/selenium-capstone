Design Pattern

Page Object Model

Each page in the application has a dedicated class. Locators never appear in test code.

Page Class

public class LoginPage extends BasePage { private final By usernameField = By.id("user-name"); private final By loginButton = By.id("login-button"); public void login(String user, String pass) { type(usernameField, user); type(passwordField, pass); click(loginButton); } }

Test Class

public class LoginTest extends BaseTest { @Test public void validLogin() { LoginPage page = new LoginPage(driver); page.login( getStandardUsername(), getStandardPassword()); Assert.assertTrue( url.contains("inventory")); } }
  • Locators are private fields in page classes only
  • Tests read like a user story, not DOM manipulation
  • Changing a locator updates one file, not every test
Infrastructure

Base Test & Utilities

BaseTest

Shared Setup/Teardown

@BeforeMethod launches browser, navigates to base URL. @AfterMethod captures screenshot on failure, quits browser. All test classes extend it.

ConfigReader

Configuration Management

All values from config.properties: browser type, base URL, credentials, wait timeouts. Nothing hard-coded in test classes.

WaitHelper

Explicit Waits

WebDriverWait wrappers for visibility, clickability, and invisibility. Zero Thread.sleep() calls in the entire codebase.

ExtentReports

HTML Reporting

Generates a detailed HTML report after each suite run. Pass/fail/skip counts, test durations, failure screenshots attached.

ScreenshotHelper

Failure Capture

Automatic screenshot on any test failure. Files named with test method and timestamp for easy debugging.

WebDriverManager

Driver Management

Automatic browser driver download and setup. Supports Chrome, Firefox, and Edge with a single config change.

Synchronization

Wait Strategy

Every dynamic interaction uses explicit waits through WebDriverWait. No hard sleeps anywhere.

What We Use

  • visibilityOfElementLocated
  • elementToBeClickable
  • invisibilityOfElementLocated
  • visibilityOfAllElements
  • urlContains

What We Avoid

  • Thread.sleep() — slow and flaky
  • Implicit waits — conflict with explicit
  • Fixed timeouts — configurable via properties
public WebElement waitForClickable(By locator) { return wait.until( ExpectedConditions.elementToBeClickable(locator) ); } // Used in BasePage — every click waits automatically protected void click(By locator) { waitHelper.waitForClickable(locator).click(); }

Automatic capture in @AfterMethod. Named with test method and timestamp. Attached to the Extent Report for each failed test.

TestNG Groups

Suite Organization

Tests grouped as "smoke" and "regression" in testng.xml. Run specific groups with -Dgroups=smoke for fast feedback.

Config-Driven

Change browser, URL, or wait times in config.properties without touching any code. No recompilation needed.

Execution

Running the Tests

# Run the full suite mvn clean test # Run smoke tests only (login + E2E) mvn clean test -Dgroups=smoke # Run regression tests only mvn clean test -Dgroups=regression # Run a specific test class mvn clean test -Dtest=LoginTest # Change browser via command line mvn clean test -Dbrowser=firefox
  • Maven handles all dependency downloads automatically
  • WebDriverManager downloads the correct browser driver
  • Reports generated in reports/ after every run
  • Screenshots saved in screenshots/ on any failure
Design Decisions

Key Technical Decisions

Why Page Object Model?

Separates locators from tests. If a UI element changes, we update one page class instead of every test that uses it. Reduces maintenance effort as the test suite grows.

Why Explicit Waits?

Each wait targets a specific condition (visible, clickable, gone). Tests run as fast as the app allows instead of waiting a fixed duration. No flaky failures from timing issues.

Why Config Properties?

Switching browsers, environments, or timeouts requires no code changes. The same tests run against dev, staging, or production by changing one file.

Why WebDriverManager?

Eliminates manual driver downloads and PATH configuration. Automatically matches driver version to installed browser. Works across operating systems.
